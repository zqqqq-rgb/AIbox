# 后端单功能验收：事件详情查询

日期：2026-11-10。状态：开发、自动测试及本地接口实测已完成，等待用户验收。

## 本次仅交付一个功能

`GET /api/events/{id}`：根据本地事件 ID 查询已保存事件的详情。

业务查询放在 `business/event_service.h/.cpp`，HTTP 路由复用原有鉴权。查询不依赖摄像头或引擎在线，不下发引擎命令，不修改事件。本次不增加状态流转、重要标记、统计或处置历史接口。

上轮尚未集成、验证的事件处置草稿已收敛到本功能。数据库继续使用 schema v8，无需迁移；原有 `GET /api/events` 数组返回保持兼容。

## 成功返回

沿用现有 `code/msg/data` 包装。示例字段如下，具体值取决于实际事件：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 123,
    "camera_id": 3,
    "algo_id": "person",
    "type": "REGION_IN",
    "ts": 1790000000000,
    "reported": false,
    "task_id": 6,
    "rule_id": 8,
    "task_revision": 2,
    "rule_version": 1,
    "targets": [],
    "targets_valid": true
  }
}
```

- `snapshot` 仅在数据库保存了快照路径时返回；存在路径不代表对应文件已经通过可用性验证。
- 旧事件没有任务/规则来源时，来源字段返回 0。
- 历史目标 JSON 损坏时，事件本身仍可查询，`targets=null`、`targets_valid=false`；该标记只说明 JSON 是否可解析。
- `reported` 表示已有的上报标记，不等同于新增通知渠道已经送达。

## 接口验收步骤

本地演示默认地址为 `http://localhost:8080`。在 PowerShell 执行：

当前可直接验收的已有事件：`http://localhost:8080/api/events/12`。实测返回 `code=0`、`camera_id=3`、`task_id=7`、`rule_id=6`；这些是演示数据，不是现场检测效果。

```powershell
$events = (Invoke-RestMethod 'http://localhost:8080/api/events?limit=1').data
$eventId = $events[0].id
Invoke-RestMethod "http://localhost:8080/api/events/$eventId" | ConvertTo-Json -Depth 10
```

也可以从事件列表复制实际 ID，在浏览器地址栏打开 `http://localhost:8080/api/events/实际ID`。

验收关注点：

1. 正常事件返回 `code=0`，ID、摄像头、算法、类型、时间及目标信息与列表一致。
2. 有来源的事件返回正确的任务、规则及版本；历史来源不依赖当前任务是否存在。
3. 请求不存在的正整数 ID，返回业务错误 `code=1002`。
4. 请求 `/api/events/0` 或超出有符号 64 位范围的数字，返回 `code=1001`；非数字路径返回 HTTP 404。
5. 配置认证后，未登录且未提供有效 Bearer 的请求返回 HTTP 401。
6. 重复查询不改变事件或发送引擎命令。

成功与业务错误沿用 HTTP 200，认证错误使用 HTTP 401。启用认证的部署需先浏览器登录，或使用 `Authorization: Bearer <设备配置凭据>`。

若本地事件列表为空，需要先通过既有任务产生一条事件。本功能不主动创建演示事件或写入用户数据。
