# AIBox 竞品页面与当前项目差异分析 V1.0

- 分析日期：2026-10-30
- 参考资料：`doc/复刻即合页面/replica/`、`doc/复刻即合页面/device-api/`
- 当前项目范围：`web/`、`business/`、相关 `engine/` 接口
- 分析方式：静态源码与已保存 API 快照对照；未连接竞品设备，未执行本轮板端验收。

## 1. 核心结论

竞品资料呈现的产品主线是：**选择业务能力 → 配置摄像头任务 → 查看运行状态 → 告警研判与处置 → 通知或联动**。

当前项目页面主线是：**接入摄像头 → 配置算法参数和 ROI → 查看实时检测与历史事件**。业务后端已开始支持独立 V2 任务、跨摄像头配置、持久化应用和恢复，页面尚未完整承接这些能力。

主要差距集中在业务能力组织、独立任务页面、告警处置和运行诊断。解码、推理、跟踪等底层模块已有实现，是否达到交付标准仍需真实设备、模型及故障场景验证。

## 2. 参考资料的证据边界

### 2.1 静态复刻页面

`replica/assets/data.js` 明确是本地 Mock 数据层。多处按钮只弹出提示，不执行真实业务：

- `replica/pages/rules.js` 的新建任务和任务操作提示需要真机接口支持。
- `replica/pages/cameras.js` 的扫描和添加处理主要展示提示与关闭弹窗。
- `replica/pages/events.js` 的详情及状态更新提示需要设备接口支持。

因此，复刻代码可以参考导航、字段、状态表达和交互结构，不能直接作为可工作的业务前端替换当前 `web/`。

### 2.2 设备 API 快照

快照提供了某次设备状态的证据：

| 资料 | 可以确认的内容 | 不能据此确认的内容 |
| --- | --- | --- |
| `_api_algorithms.json` | 记录 7 个算法条目及其版本、能力和就绪字段 | 所有算法在全部真实场景中的准确率和稳定性 |
| `_api_algorithm_tasks.json` | 记录 2 个运行中任务及 FPS、排队和推理指标 | 完整任务启停、故障恢复与时间计划执行效果 |
| `_api_events.json` | 记录 4 条事件及来源、截图类型、处置字段 | 全部处置状态转换和证据可靠性 |
| `_api_system_product_closure.json` | 当次样本报告了 2 行正式事件闭环 | 所有能力、通道和故障条件下均闭环 |
| 通知与硬件联动快照 | 已有对应接口族，当次列表为空 | 真实渠道已经收到通知或外设已经动作 |

外部返回的 `runtime_ready`、`formal_event_ready` 等字段是对方系统的状态报告，不等于本项目具备同样能力，也不能代替独立实机验证。

## 3. 主要功能对照

| 维度 | 竞品页面或快照表现 | 当前项目 | 差距性质与后续工作 |
| --- | --- | --- | --- |

| 任务管理 | 独立算法任务页，按摄像头聚合任务，展示算法与告警条件、运行状态和操作 | 已有 V2 草稿、启停、部署状态 API；前端仍以摄像头算法配置为主 | 优先补任务页，复用现有业务服务和恢复机制 |

| 告警事件 | 来源链、事件阶段、身份关联、处置状态、重要标记、处理人员与备注字段 | 已有事件保存、来源 ID/版本、截图和查询；缺完整处置接口 | 补事件详情、状态流转、审计、统计、证据状态与恢复 |
| 通知中心 | 渠道、路由、投递记录页面和接口；快照列表为空 | 已有 Outbox 与重传结构，当前主程序 MQTT 发布器为占位实现 | 补选定渠道真实投递、确认、重试和投递状态 |
| 硬件联动 | 端点、规则、动作记录、解除输出入口；快照列表为空 | 当前未见完整对应业务服务与接口 | 先确定设备和协议，再做适配、动作状态及恢复 |
| 人脸底库 | 有底库管理及特征/比对能力状态接口 | 当前未见完整底库及识别业务闭环 | 依赖真实模型与特征协议；对方快照也显示识别尚未就绪 |
| AI 研判 | 有配置与任务/结果接口；快照显示尚需配置提供方 | 当前未见对应业务功能 | 可列后续扩展，不自动加入本轮任务 |
| 系统运维 | 系统分区较多，有日志、网络、预检和产品闭环快照 | 已有资源状态、引擎状态、配置操作、清理和基础 Token | 补日志诊断、配置管理、统一认证与部署恢复；页面中的 OTA 入口不能证明完整升级能力 |
| 录像 | 页面主要围绕事件及证据组织 | 当前有独立录像检索和 MP4 播放页面 | 保留已有能力，补事件到相关录像的清晰关联 |
| 外网固定域名 | 网络快照含 `.local` 形式地址，没有足够证据证明公网访问链路 | 当前 WebSocket、信令和录像地址仍需外网入口适配 | 按负责人新增需求独立建设，不能依据竞品页面推定已完成 |

## 4. 算法目录、任务与时间指标的具体差异

### 4.1 业务能力数量与模型数量不同

复刻资料中的 103 项是业务能力目录，不是 103 个独立模型。设备算法快照只有 7 个算法条目，目录中也存在“待接入”和“待就绪”状态。

例如，同一个人员检测模型可以为区域入侵、驻留或人数规则提供输入；姿态、车牌识别、人脸比对等能力则需要相应模型、后处理或级联支持。

当前项目可以借鉴目录的表达方式，但“可用”状态应来自本机真实模型、规则实现与验证结果。仅给能力绑定某个模型 ID 不足以证明业务能力已经实现。

### 4.2 任务运行指标

竞品任务快照中的两条样本：

| 算法 | 目标 FPS | 实际 FPS | 平均排队时间 | 平均推理时间 | 触发间隔 |
| --- | --- | --- | --- | --- | --- |
| 人员检测 | 2 | 约 1.923 | 约 0.159 ms | 约 31.569 ms | 30 s |
| 姿态检测 | 2 | 约 1.923 | 约 30.541 ms | 约 99.671 ms | 30 s |

这些数值仅描述保存快照时的状态。快照未充分定义统计窗口、推理耗时包含阶段等口径。

当前项目已有：

- 模型级 `npu_cost_ms`，用于资源预算，定义为仅 `rknn_run` 耗时，来自清单回填或自测。
- 队列深度、采样 FPS、各阶段输入/输出/丢弃计数及资源状态。
- V2 任务的部署版本、应用状态和操作记录。

当前尚缺前端可直接使用的完整任务级“实际 FPS、平均等待时间、运行耗时、丢帧原因”等展示链路。补齐这些指标需要引擎提供对应统计、业务层建立任务关联、前端展示，不只是新增 API 字段。

**不能将对方的 `avg_inference_ms` 与本项目 `npu_cost_ms` 直接比较速度。** 对方样本算法标识为 RK3576，当前项目开发基线为 RK3588，模型、输入、精度、硬件和统计口径也不相同。

### 4.3 三种时间概念应分开

| 时间概念 | 含义 | 当前项目情况 |
| --- | --- | --- |
| 推理耗时 | 完成一次模型执行或某段处理所需时间 | 已有模型 NPU 耗时及部分链路统计，需完善任务级运行指标 |
| 规则持续与告警间隔 | 目标持续满足多久、连续告警如何抑制 | 已有驻留、防抖等规则参数；与对方 `trigger_interval_sec` 的语义需单独对齐 |
| 时间计划 | 哪些日期、时段启用任务 | 当前可保存、校验和预览计划，运行时定时切换尚未集成 |

竞品任务快照中的 `task_config` 没有提供足够的周计划执行证据，不能据此认定对方已完成时间排班闭环。

## 5. 当前项目可复用的基础

1. 三进程分工明确：ZLM 负责媒体，engine 负责分析，businessd 负责配置和事件编排。
2. 摄像头发现与取流已有真实后端实现，当前项目在此项上的工作重点是补齐产品体验与实机验证。
3. 配置具有目标版本、确认版本和操作记录，Reconciler 可执行与重试，重连可重放。
4. V2 任务已支持无时间计划的持久化启停、跨摄像头操作和部署状态查询；任务状态不只由一个 `enabled` 字段决定。
5. 事件已保存任务、规则及版本来源，可继续扩展处置和证据业务。
6. 已有 Fake、Mock 与进程恢复测试基础，可用于新增业务的可重复验证。

上述为本仓库可检查的实现基础，不构成与竞品可靠性高低的比较结论。本轮未重新运行测试。

## 6. 面向业务层的建议优先级

| 优先级 | 工作 | 建议验收结果 |
| --- | --- | --- |
| P0 | 摄像头发现与接入完善 | 用户可选择扫描范围，发现设备、认证、取流并成功预览；失败有明确状态 |
| P0 | 固定域名外网访问 | 外网通过 HTTPS 入口完成配置、WS 推送、视频与录像访问 |
| P1 | V2 算法任务页面 | 创建、编辑、启停、查询逐摄像头部署结果，并能解释失败与等待状态 |
| P1 | 事件处置与证据 | 能查看详情、标记重要、处理或忽略，截图失败与重试状态可追踪 |
| P1 | 业务能力与就绪诊断 | 展示真正支持的能力、模型依赖和阻塞原因，不将目录项全部标为可用 |
| P2 | 时间计划与任务指标 | 定时启停、重启恢复；显示定义明确的 FPS、延迟和丢弃指标 |
| 按选型推进 | 通知、人脸与硬件 | 选定渠道、模型或外设后完成真实闭环，分别保留模拟与实机验证记录 |

P0 对应负责人刚明确的两项需求。其余功能参考竞品成熟的业务组织方式，逐项进入本项目交付范围，避免一次性照搬所有菜单。
