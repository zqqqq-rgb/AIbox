# businessd 第二阶段第四批实施记录

日期：2026-11-02。承接第三批任务持久化启停，本批交付固定 UTC 偏移的每周时间计划执行，以及连接真实 REST 接口的 V2 任务管理页面。

## 完成内容

1. **时间计划执行**：CameraService 每秒检查已启用定时任务，按当前窗口生成全部关联摄像头的目标配置。在同一 SQLite 事务中更新摄像头操作及任务部署关联，继续由 Reconciler 下发、确认和重试；不是只在页面上切换状态。
2. **时间语义**：支持 `UTC`、`UTC±HH:MM`（最大 ±14:00），星期一至星期日位掩码、起点包含/终点不包含、跨午夜归开始日。多个窗口取并集，窗口重叠不重复创建操作。无窗口的任务持续执行，手动停用优先于时间计划。
3. **重连与重启**：UDS 同步在重放前先重新计算当前窗口，替换离线期间已过期的目标。业务重启和引擎重连共用此入口。时间检查不改用户任务 revision，也不改规则版本，来源标识保持一致。
4. **峰值资源预留**：启用和摄像头变更时，对所有已启用任务预留模型峰值 FPS，包括当前窗口外的定时任务；不会把不同时段当成可以无条件超售的资源。预检返回 `reservation_policy=all_enabled_peak`。该策略较保守，即使窗口互斥也可能拒绝一组高负载任务。
5. **状态与交互**：任务返回 `schedule_active`、`schedule_runtime_supported` 和 `waiting_schedule`。窗口边界已到但新配置未保存/确认时，不把旧确认显示为当前目标已应用。启停响应补充 `pending`，前端能够保留已受理的多摄像头操作信息。
6. **任务页面**：新增导航“算法任务”及 `#/tasks`，支持新建/编辑/删除草稿，多摄像头、多算法、多个入侵/驻留规则，阈值、FPS、防抖、区域顶点绘制/输入，以及多个每周时间窗口。支持启停、每两秒刷新状态、查看摄像头执行详情和预检摄像头计划。运行中及停用未确认的任务禁止编辑，草稿轮询不会覆盖正在输入的内容。

没有新增数据库迁移，schema 仍为 v8；时间切换复用不可变配置操作和 `task_deployments`。仅当编译后的目标发生变化时保存新操作。

## 当前边界

窗口以每秒检查方式最终收敛，依赖系统时钟；不是实时硬件定时器。网络断开、引擎忙或失败重试期间，实际生效会延后；重连后应用当前目标，不补跑错过的历史窗口。不支持 IANA 时区及夏令时。

区域画布是归一化坐标示意图，不是真实视频底图。fake 模型仅生成固定检测框，MockZlm 不提供真实视频、截图或录像。本批没有板卡/RKNN/MPP/RGA、真实摄像头或外设验收。
