## 2. 目录结构与模块职责

```
web/
├── index.html              # SPA 壳：侧边导航 + <main> 路由出口 + 全局 toast/modal 容器
├── app.js                  # 哈希路由 + 页面装配（每页一个 render 函数，返回 DOM 节点 + unmount）
├── api.js                  # REST 封装：envelope 解包、错误码→toast、Bearer 预留
├── ws.js                   # WS 单例管理：/ws/events 常驻 + /ws/meta/{cam} 按页租借（引用计数）
├── player.js               # CamPlayer：ZLMRTCClient 封装 + 指数退避重连（1s→8s）
├── overlay.js              # DOM 薄壳：rAF 驱动 + canvas 管理，计算全部委托 overlay_core
├── overlay_core.js         # ★纯函数（无 DOM）：锚定/对齐/插值/淘汰/fitRect/绘制数据
├── ui.js                   # toast / confirmModal / badge / 三态视图（loading/empty/error）
└── vendor/ZLMRTCClient.js  # ZLM 自带（随 MediaServer www 目录，拷入）
```

**模块纪律**（对应 T5.1 可测试性）：

- `overlay_core.js` 只 import 标准 JS，不碰 `document/window`；全部状态以参数传入、返回新状态（可序列化，便于回放测试）；
- `overlay.js` / `player.js` 是薄壳：DOM 事件 → 调纯函数 → 画 canvas，不含对齐/插值逻辑；
- `ws.js` 统一管理重连与订阅租借，页面不得自行 `new WebSocket`。

## 4. 通用规范

### 4.1 REST 约定（api.js）

- 所有响应为 envelope `{"code":0,"msg":"ok","data":...}`（详设§8.1）；
- `code !== 0` → 抛 `{code, msg}` 并 **toast 错误文案**：优先用后端 `msg`，`msg` 为空时按 §8.2 错误码表映射兜底文案（如 `3001`→"NPU 算力预检超限，请降低检测帧率"）；
- 超时 8s（板上 ZLM getServerConfig 实测 >2s，放宽）；失败 toast 统一红底。

### 4.2 三态视图（ui.js）

每个数据区（列表/面板）统一三态：

- **loading**：骨架条或转圈；
- **empty**：灰字提示 + 引导动作（如摄像头空列表 → "添加第一台摄像头"按钮）；
- **error**：红字 + 重试按钮（保留入参重发）。

### 4.3 徽标与状态色

| 状态      | 色            | 出现处                                                        |
| --------- | ------------- | ------------------------------------------------------------- |
| 在线/正常 | 绿`#34c77b` | 摄像头 online、engine_online                                  |
| 离线/失败 | 红`#e5484d` | camera_status online=false、API 错误 toast                    |
| 降级/警告 | 橙`#f5a524` | WS degrade 事件、NPU 预估 >80%                                |
| 禁用/未知 | 灰`#6b7280` | algorithms.disabled、后端占位字段（rss/disk=0 → 显示`--`） |

### 4.4 WS 管理（ws.js）

- **常驻**：`/ws/events`（进入页面即连，全局事件分发：`event`/`camera_status`/`degrade`/`registry_ready`）；
- **租借**：`/ws/meta/{cam_id}` 按页面租借（宫格多路、单路一路），**同一 cam 多 viewer 引用计数**（后端已做 sub_meta 去重，前端亦计数防重复订阅）；页面 unmount 必须归还；
- 重连：指数退避 1s→2s→4s→8s 封顶；重连成功后**清空本地 overlay 状态并要求重新锚定**（`overlay.reset()`）；
- 心跳：后端 30s ping（浏览器自动 pong），前端 60s 无任何消息视为死连主动重连。

## 5. 页面设计

### 5.1 #/grid 监控宫格（核心页）

```
┌─────────────────────────────────────────────────────────┐
│ [1路] [4路] [9路]                    （视角: 子码流 AI）  │
│ ┌───────────────┬───────────────┬───────────────┐       │
│ │ ●cam-1  12:03 │ ●cam-2  12:03 │ ○cam-3 离线   │       │
│ │  [video]      │               │   灰底        │       │
│ │  [canvas 框]  │               │               │       │
│ └───────────────┴───────────────┴───────────────┘       │
│ ┌───────────────┬───────────────┬───────────────┐       │
│ │ ...           │               │               │       │
│ └───────────────┴───────────────┴───────────────┘       │
└─────────────────────────────────────────────────────────┘
```

**格子（Tile）构成**：`video（WebRTC）+ canvas（检测框）+ 左上徽标（名称/在线灯）+ 右上时间戳`。

数据与生命周期：

| 步骤 | 动作                                                                    | 接口                                                            |
| ---- | ----------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1    | 拉摄像头列表                                                            | `GET /api/cameras`                                            |
| 2    | 按 N 取前 N 路建 Tile（online=false 只渲染灰底，**不建 player**） | —                                                              |
| 3    | 每 Tile 取信令并起播放                                                  | `GET /api/cameras/{id}/stream?quality=sub` → CamPlayer.start |
| 4    | canplay 后 canvas 定尺寸 + overlay 锚定就绪                             | `video.videoWidth/Height`                                     |
| 5    | 订阅元数据流                                                            | `ws.js` 租借 `/ws/meta/{id}`                                |

交互：

- **单路放大**：单击格子 → `#/grid?cam={id}` 进入 focus 视图（大画面 + 底部该路信息：算法/阈值摘要、`dec/in out` 指标摘自 `GET /api/resources`）；focus 视图**销毁宫格全部 player 实例**（浏览器解码器配额），只建 1 路；返回/后退键回宫格重建；
- 宫格上限 9 路同时播放（第 10 路起显示 "未在显示中" 占位，点击置顶替换）；
- 切换路由离开本页：**unmount 销毁全部 player + 归还全部 WS 租借**（性能纪律 §8）。

异常态：某路 player 重连中 → 格子内转圈 + "重连中"；连续失败 8s 退避 3 次后 → 红字 "连接失败（点击重试）"。

### 5.2 #/cameras 摄像头管理

```
┌────────────────────────────────────────────────────┐
│ [＋添加摄像头]                                     │
│ ┌──────────────────────────────────────────────┐   │
│ │ ● cam-1   rtsp://…main   算法×2   [配置][编辑][删除] │
│ │ ○ cam-2   rtsp://…main   算法×0   [配置][编辑][删除] │
│ └──────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────┘
```

- 列表字段：online 徽标（WS `camera_status` 实时翻转，无需轮询）、名称、`rtsp_main`、已配算法数；
- **添加弹窗**（表单）：`name` / `rtsp_main` / `rtsp_sub` / `enabled`；说明文字注明 "添加后自动创建 ZLM 代理并下发 engine"；
  - `4002`（ZLM 建代理失败已回滚）→ toast 红；
  - 成功但 engine add 失败（响应 `data.note` 存在）→ **黄色警示条**展示 note："engine 添加失败（代理已建），可重试 enable 或删除"；
  - `probe` 字段 V1 为占位（详设§5.4-1），**不渲染探测结果**；
- **编辑**：`PUT /api/cameras/{id}`（name/rtsp 地址）；
- **删除**：confirm modal 明示级联后果（ZLM 代理 + engine 通道 + 记录一并删除）→ `DELETE /api/cameras/{id}`；
- 每行 "配置" 快捷跳 `#/config?cam={id}`。

### 5.3 #/config 通道算法配置（算力预检前移页）

```
┌───────────────────────────────────────────────────────┐
│ 摄像头: [▼ cam-1]                    NPU 预估: 34% ▓▓▓░│
│ ┌─────────────────────────────────────────────────┐   │
│ │ ☑ person-det   阈值[0.45] 帧率[3]fps  (常驻)     │   │
│ │ ☐ face-det     阈值[0.50] 帧率[2]fps  (触发)     │   │
│ │ ROI: （V1 只读显示，编辑器后置 §9-D3）            │   │
│ └─────────────────────────────────────────────────┘   │
│ [保存并热生效]        （PUT 响应含 npu_est 实时刷新）   │
└───────────────────────────────────────────────────────┘
```

- 左下拉选摄像头（URL 参数 `?cam=` 直达）；右算法列表来自 `GET /api/algorithms`（disabled 置灰不可选）+ 当前勾选态来自 `GET /api/cameras`（`algos` 数组）；
- **保存**：`PUT /api/cameras/{id}/algos` → 热生效（RECONFIG，百 ms 级）；
- **NPU 预估显示**：保存响应 `data.npu_est`；勾选变化时本地即时预演（前端不可算后端公式，只提示 "保存后生效"）；
- 预检拒绝处理：`3001/3002` → toast 展示后端 `msg`（含 "camN fps →3 可降至 XX%" 建议），**表单不关闭**，用户降 fps 后重试；
- `1003`（状态不允许，如通道 RECONFIG 中）→ toast "通道正在配置中，稍后重试"。

```
┌───────────────────────────────────────────────────────────┐
│ algo_id     name    version  model_ref  cost(ms) mem(KB)  │
│ person-det  人体    v3       y8n.rknn   18.2     8192    │
│             classes: [person]  trigger: 常驻              │
```

- 数据：`GET /api/algorithms`；`disabled=true` 行置灰 + 徽标（坏包不拖垮启动，用户可见不可用原因需 hover 提示 "包校验失败或平台不符"）；

### 5.5 #/events 事件中心

> 实现变更（2026-10-14）：原"实时流 | 历史检索"左右双栏合并为**单列表**——实时区删除，
> WS 实时事件按当前筛选条件头插进历史列表（上限 100 与查询一致；空态占位有事件进入即清除）。

```
┌────────────────────────────────────────────────────────────┐
│ [摄像头▼][算法▼][起][止] [查询] ☐实时   （单列表布局）    │
│ ┌──────────────────────────────────────────────────────┐   │
│ │ts  cam  algo  type  快照（"实时"勾选时 WS 头插顶部）  │   │
│ │...（点击行 → 大图 modal）                            │   │
│ └──────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────┘
```

- **实时头插**：WS `/ws/events` 的 `event` 类型 → "实时"开关（默认勾选）→ 过滤（摄像头/algo/时间范围与查询表单同源）→ 列表头部插入；开关关闭时列表保持查询态（页内 WS 订阅不断，仅不入列表）；businessd 落库先于广播，与查询竞态由后续查询自然收敛；头插行 2s 后按 cam+时间窗静默单查自动回填快照徽标（截图落盘 ~0.5s 后 DB 才有路径；仍无快照 = 截图失败，保持灰显，下次查询兜底）；
- **全局 toast**：右下角卡片（5s 自动消失，点击跳 `#/grid?cam=`）为页面无关的全局行为，保留；
- **历史查询**：`GET /api/events?camera_id&algo_id&from&to&limit`（limit 默认 100）；`from/to` 为 datetime-local 控件换算（实现为 ms）；
- 快照缺失（后端 `snapshot` 字段可缺省）→ 灰色占位图标，**不破版**；
- targets 展开显示：`track_id + cls + conf`。

## 6. 检测框叠加管线（overlay 模块契约）

### 6.1 坐标系与 fitRect（前端版 letterbox）

检测坐标为**检测域分辨率**（子码流原始分辨率，如 640×480）；canvas 尺寸 = 容器 CSS 像素。两域不同 → 绘制前经 `fitRect`：

```js
// 纯函数：等比 contain 铺满 + 居中偏移（与 RGA letterbox 同构，往返误差 0）
fitRect(srcW, srcH, dstW, dstH) -> {scale, ox, oy}
// 绘制: x' = x*scale + ox, y' = y*scale + oy, w' = w*scale
```

canvas.width/height = 容器 clientWidth/Height × dpr（cap 2x），CSS 铺满格子；video 用 `object-fit: contain`——**video 的实际渲染矩形与 canvas 变换同源**（同一 fitRect），框与画面天然对齐。

### 6.2 overlay_core.js 纯函数清单（T5.1 单测对象）

```js
computeAnchor(mode, fp_us, videoEdgeSec)   // 锚定：返回 anchorFp（null=未锚）
alignTick(detQ, tracks, anchorFp, vc_us, nowMs)  // 对齐+淘汰，返回 {objs, detQ, tracks}
extrapolate(objs, tracks, nowMs, maxAgeMs=1000)  // vx/vy 线性外推，超龄剔除
fitRect(srcW, srcH, dstW, dstH)                  // §6.1
drawData(objs, fit, cw, ch)                      // 输出纯绘制指令（strokeRect 参数+标签文本），DOM 层照抄执行
```

- `detQ` 容量 64 丢最旧（详设§6.3，原 demo 30→64）；
- 逐帧对齐：弹出所有 `frame_pts ≤ vc_us` 取最新；陈旧（`vc - fp > 2e6`）直接丢；
- track 超 1s 未更新剔除；`track_id` 作 map 键。

### 6.3 锚定双模式（★本文裁决，回改详设§6.3 注记）

| 模式                     | 视频通道                    | 锚定公式                                                                                                             | 残差                                  |
| ------------------------ | --------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| `mse`（demo 已实测）   | MSE-FLV（flv.js）           | `anchorFp = fp_最新 - buffered.end() × 1e6`（缓冲前沿≈实时；**忌用 currentTime**）                         | ~0.2s                                 |
| `webrtc`（产品主模式） | ZLMRTCClient（MediaStream） | `anchorFp = fp_最新 - currentTime × 1e6`（WebRTC 无播放缓冲，播放头≈实时边缘，onPlaying 后首条 detections 对拍） | jitter buffer~0.1~0.3s，框整体微滞后 |

- 两种模式**仅在 `computeAnchor` 一处分叉**，下游对齐/外推完全复用；
- 依据：WebRTC 的 MediaStream 直接渲染，`video.buffered.length === 0`，详设§6.3 的 buffered 公式在 WebRTC 下失效；而 WebRTC 无 seek 缓冲，currentTime 即实时边缘，满足"实时边缘对拍"的本质条件；
- **重锚**：player 重连成功、页面重进、WS 重连 → `anchorFp=null` 重新锚定（锚定只发生一次，锚后不变——详设原则保持）。

```
app路由→#/grid → GET /api/cameras → 逐Tile: GET .../stream?quality=sub
  → ZLMRTCClient.Endpoint(start) → onPlaying → canvas定尺寸(videoWidth/H)
```

```
degrade        → 顶栏降级徽标（橙）+ settings页当前级别
registry_ready → algos页整表重拉 + 绿条提示
```

## 8. 性能与资源纪律

1. **player 实例数 ≤ 可视路数**：切页/缩小宫格必须 `destroy()`（WebRTC 解码器配额有限；宫格 9 路已近上限）；
2. 宫格/单路**强制子码流**（架构§10.4-1，8×1080p 浏览器解码卡死）；
3. canvas rAF 统一 30fps；页面不可见（`document.hidden`）时暂停 tick（WS 照收，回页重对齐——detQ 会补齐弹出最新）；
4. `/ws/meta` 每路约 3fps 消息，9 路峰值 27msg/s，JSON 行 <1KB——无压力；
5. 静态资源总量目标 <300KB（无框架纪律的收益）；ZLMRTCClient ~200KB 为大头。
